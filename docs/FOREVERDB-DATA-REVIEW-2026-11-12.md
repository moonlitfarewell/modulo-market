## Player problem and observable result

The addon previously bundled ForeverDB recipe structure from build `1.60.1.70862` while the player's client and market snapshot were `1.60.1.70888`. This refresh adopts the new build-matched recipe baseline without discarding the older canonical file or relaxing the exact-current-build auction snapshot gate. The observable result is that the addon can identify its recipe catalogue as build-matched on client 70888; auction economics still independently requires a 70888 market snapshot.

## Compatibility and ownership

- Only the optional `ModuloMarket` child addon and its owned data/docs/tests are changed. Parent MODULO 1.0.48 remains unchanged and ModuloMarket still depends on MODULO, never vice versa.
- Runtime dataset build is now exactly `1.60.1.70888`; `ProfessionData.lua` retains the exact build check.
- The saved Browse/Replicate market snapshot must still independently match the running client build before auction prices can be joined to recipe data. This data refresh does not bypass that gate.
- Existing per-field distinctions remain: `FOREVER_CLIENT`, `FOREVER_OBSERVED`, `CLASSIC_BORROWED`, `UNKNOWN`; speculative records remain excluded from the runtime item-craft catalogue; non-item/unknown-output records remain separately counted.
- ForeverDB attribution remains visible in the Market and in generated metadata. No API key or raw capture archive is included in the public addon update.
- The previous `ForeverDB-Canonical-1.60.1.70862.json` remains in the repository as historical provenance; it is not deleted or relabelled.
